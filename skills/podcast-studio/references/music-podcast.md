## 1. 全流程总览

```
选题（栏目定位+类别轮换/热点）→ 标题+简介 → 选曲清单（逐首版权验证）
→ 文稿创作 → 事实核实（杜绝幻觉）→ 封面 → 待审核推送
→ 运营回复"发" → 发布脚本走后台流程 → 落库记录
```

**人机分工红线**：AI 预产到"待审核"状态停下；发布闸门永远在用户手里，用户说"发"才流转。

## 2. 选题与栏目定位

- 栏目化运营：每个栏目先有定位宣言（如"时空情书=过去写给现在的信，那年今月的歌+音乐时空机两个系列"），选题不跑偏
- 类别轮换防重复：导演专题/古装剧盘点/台偶盘点/歌手专题轮换，首次回补要标注
- 热点响应：「今天谁火了写一期」类需求，补充关键背景（如"旋律改编自XX"）后快速成稿

## 3. 标题与简介

标题格式（已验证两种）：
- `歌手《专辑》：XX年前，XXXX`
- `2004年：一个沙哑的嗓子，把整个华语歌坛吵醒了`

简介要点：一个意象贯穿（拆信/时光机）、3-4 个钩子问句、时间跨度、情感承诺；**末尾必须加**「作者声明：节目包含由AI创作生成的内容。」

## 4. 选曲与版权验证

- 每期 7 首左右，总时长约 23-25 分钟：过渡曲 1 + 讲解曲 5 + 收尾曲 1
- 逐首验证版权状态并标注：fee=0 免费 / fee=1 VIP / fee=8 SVIP；记录歌曲 ID、演唱者、出处年份
- 版权风险提示前置：如"7首全VIP，同《XX》先例，需你确认"
- 禁止播放重复歌曲；开场曲只轻轻带过；收尾曲可不配讲解

## 5. 文稿结构

```
【开场钩子】≤100字，一个场景化问句切入（钩子丢了会被打回，人物故事不许堆在开头）
（→ 过渡曲，轻轻带过）
【讲解1-5】每首歌一段：年代+作品背景+歌曲故事+人物经历+冷知识+词曲作者
（→ 歌曲）
【结语】收主题 + 金句升华 + 引导评论订阅 + 收尾曲引入
```

- 讲解密度标准：每首含至少 1 个冷知识或幕后故事（如黄霑写《沧海一声笑》六稿被退、倒转五声音阶"羽徵角商宫"的典故）
- 人声占比可量化调控：20% 基准 → 30% 增厚（通过增加歌曲故事/人物经历实现）
- 开场钩子与人物故事分层：钩子≤100字在前，人物故事下放到讲解和结语

## 6. 事实核实清单（发布前硬门禁，用户原话："杜绝幻觉"）

逐项核查：
- [ ] 年代/年份是否准确
- [ ] 人物故事、身份关系是否准确
- [ ] 封面描述与实际图一致
- [ ] 有无表述过于绝对（"最""第一""公认"需有依据）
- [ ] 多音字播讲是否正确（见第 7 节）
- [ ] 歌曲 ID/演唱者/词曲作者与选曲清单一致

## 7. 多音字与播讲工程化

- TTS 踩坑规则：多音字不逐处标读音，**批量替换为播讲友好的近义词**。例：「港乐」（TTS 易念 yuè）→「香港歌坛」，33 处+2 处脚本批量替换；先换长词再换短词避免误伤（先"乐坛"后"港乐"）
- 英文词播讲清晰化：rapper → 说唱歌手
- 替换后重走发布流程，不只改本地稿

## 8. 封面制作双轨

- **轨道A·AI 生成**：AI 生图文字必乱码 → 采用"AI 生成纯意象底图 + PIL 叠加正确文字"，保证标题零错字；1920×1920
- **轨道B·官方原图**：抓官方封面/艺人图，尺寸 ≥640×640（正方形）即可直接用
- 用户说"我就要原版封面"时切轨道 B，不争辩

## 9. 发布流程与自动化

- 发布：写发布脚本走 CIO 后台流程，成功后落库记录（期数/标题/发布时间）
- 定时预产：可配定时任务（如"OST时光机-周日生成周一文稿"），产出待审核文稿推送；注意设置超时与失败告警
- 发布后资产归档：文稿/封面/选曲清单落库，供后续"重发""改词重发"调用
