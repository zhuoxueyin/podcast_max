# 音乐播客创作 Workflow

音乐播客面向成年人，重"选题 + 版权选曲 + 文案 + 封面 + 发布"，可多档栏目并行。

---

## 完整流程（六步）

```
选题 → 选曲(版权验证) → 文稿 → 封面 → 质检 → 发布
```

---

## 1. 选题

**选题策略**：
- **蹭热点**：谁火了写一期（如"今天谁火了，写一期对比新老歌词"）
- **类别轮换**：栏目化运营，按类别轮换（导演专题、古装剧盘点、台偶剧盘点、年份专题、歌手专题）

**标题公式**（时空情书栏目示例）：
- `歌手《专辑》：XX年前，XXXX`
- `199X年：XXX`

**标题要求**：有钩子、有年代感、一句话抓住情绪（如"2004年：一个沙哑的嗓子，把整个华语歌坛吵醒了"）。

---

## 2. 选曲（版权验证，硬约束）

- 逐首验证版权 fee：`fee=0 免费` / `fee=1 VIP` / `fee=8 SVIP`
- 按结构组曲：**过渡曲 + 讲解曲(1~N首) + 收尾曲**
- 版权决定能否用完整音频：5 首 SVIP + 1 首 VIP + 1 首免费 是常见组合
- **全 VIP 时需用户确认**（先例：太阳的后裔 8 首全 VIP、鬼怪 7 首全 VIP）

**选曲清单格式**：
```
类型｜歌曲名｜演唱者｜歌曲ID｜出处
过渡曲｜XX｜XX｜ID｜专辑/年份
讲解1｜XX｜XX｜ID｜...
收尾曲｜XX｜XX｜ID｜...
```

---

## 3. 文稿（结构模板）

详见 `assets/templates/music_episode.md`。核心结构：

```
【开场钩子】(≤100字，一句话抓人)
【事件还原】(故事背景 + 人物经历，杜绝幻觉)
【歌曲讲解】(每首：冷知识 / 词曲作者 / 歌曲故事)
【结语】(情感升华 + 互动引导 + 订阅引导)
```

**关键约束**：
- **开场钩子 ≤ 100 字**：不能丢钩子，人物故事放后面讲解里
- **人声占比**：默认 20%，可要求 30%（更多解读、歌曲故事、人物经历）
- **讲解密度**：歌曲讲解要多（冷知识、词曲作者），不只是播放

---

## 4. 封面

- **AI 生成底图 + 程序叠字**：AI 直接生成中文标题会乱码，正确做法是 AI 生成纯意象底图 + 用 PIL 叠加文字，保证标题零错字
- 或用官方艺人图（1000×1000 / 1973×1973，≥640 达标）
- 尺寸标准：1920×1920 像素达标

---

## 5. 质检（准确性是硬红线）

**杜绝幻觉，逐项核实**：
- 封面描述、年代、人物故事是否准确
- 是否有表述过于绝对
- 年份、多音字的播讲细节

**多音字处理（TTS 前必做）**：
- 例：「港乐」的「乐」要念 yuè → 按规则改成近义词「香港歌坛」，避开多音字
- 「香港乐坛」→「香港歌坛」
- 批量替换时注意顺序（先换"乐坛"再换"港乐"，避免误伤）

---

## 6. 发布

- 写发布脚本走流程，落库记录
- 支持 Cron 定时任务（如"周日生成周一文稿"）

---

## 栏目化运营要点

- 一档栏目可拆多个系列（时空情书分"那年今月的歌"+"音乐时空机"两个系列）
- 每个系列有独立定位文案
- 作者声明：节目包含由 AI 创作生成的内容

---

## 音频生成

文稿定稿后，用 `scripts/tts_minimax.py` 合成音频。注意：
- 先做多音字替换，再合成
- 语速/音调/情绪参数按栏目调性设置
